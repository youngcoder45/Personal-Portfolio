# Portfolio architecture

> Current-state reference for the Astro portfolio at `aditya-verma.me`.
> Describes what exists today, the invariants that must survive the redesign,
> and the known technical debt that the roadmap should address.

- **Repository:** `/home/aditya/Documents/github-1/Portfolio`
- **Snapshot date:** 2026-11-12
- **Status:** audited, unmodified (documentation only)
- **Verification:** `npm ci`, `npm run check`, and `npm run build` all pass

## 1. Stack

| Concern | Implementation |
| --- | --- |
| Framework | Astro 5.15 (static output) |
| Language | TypeScript, strict Astro checks |
| Content | Astro content collections + MDX (`@astrojs/mdx`) |
| Styling | One global vanilla CSS file, 1,956 lines |
| Client scripts | Vanilla TypeScript modules bundled by Astro |
| Feed / discovery | `@astrojs/rss`, `@astrojs/sitemap`, `public/llms.txt`, `public/llms-full.txt` |
| Social image | Build-time PNG generated by `scripts/generate-og.mjs` |
| Hosting | Netlify (static publish, redirects, security headers) |

Deliberately absent: UI framework, CSS framework, animation library, analytics,
icon package, font loader, database, and runtime server.

### Commands

```bash
npm ci            # install
npm run dev       # local dev server
npm run check     # astro check (types + templates)
npm run build     # prebuild OG image, then static build
npm run check:links # audit internal href/src targets and anchors in dist/
npm run verify    # check + build + link audit
npm run preview   # preview dist/
npm run og        # regenerate public/og.png
```

## 3. Rendering and request flow

The site is fully static. There is no runtime server or API route.

```
MDX + TS data
   │
   ├─ content collections (Zod validation)
   ├─ page frontmatter (getCollection / render)
   │
   ▼
Astro components ──► HTML + scoped styles + bundled scripts
   │
   ├─ inline theme boot script (pre-paint)
   ├─ JSON search index embedded in every page
   ├─ JSON-LD graph
   │
   ▼
dist/ ──► Netlify CDN
```

Build-time work:

1. `scripts/generate-og.mjs` renders `public/og.png` from an inline SVG.
2. Astro renders every route.
3. The sitemap integration derives `lastmod` only for notes with a real `pubDate`.

Runtime work is limited to:

- Theme application and persistence.
- Boot screen dismissal (`sessionStorage`).
- Command palette search.
- Interactive terminal emulator.
- Theme picker.
- Footer clock (IST).
- Scroll/reveal behaviour defined in CSS.

## 6. Client script architecture

| Module | Entry | Responsibility |
| --- | --- | --- |
| `scripts/theme.ts` | `Layout.astro` | Apply theme, persist to `localStorage`, sync theme menu and icon |
| `scripts/palette.ts` | `Layout.astro` | `⌘/Ctrl+K` palette, fuzzy search, keyboard selection, actions |
| `scripts/rail.ts` | `SectionRail.astro` | Centre-band section tracking, `aria-current`, top-nav anchor sync |
| `scripts/progress.ts` | `ReadingProgress.astro` | Fixed-bar reading progress on long-form pages |
| `scripts/shell.ts` | `Term.astro` | Terminal prompt, history, command dispatch |
| `scripts/linux.ts` | imported by shell | Simulated Linux commands and easter eggs |
| `scripts/types.ts` | shared types | Terminal command typing |
| inline boot script | `Layout.astro` | Apply stored theme before paint; suppress boot screen after first visit |
| inline footer script | `FooterBar.astro` | IST clock, updates every second |

The palette reads a JSON index embedded by `Layout.astro` (`#search-content`)
containing published notes and all projects. This keeps content search current
without shipping a separate fetch.

### Terminal

The terminal is the signature interaction. It supports a prompt, history,
command dispatch, and simulated Linux commands. It is progressively enhanced:
a `<noscript>` block shows a static neofetch and skill summary when JavaScript
is unavailable.

## 7. Design system

### Tokens and themes

`global.css` defines CSS custom properties for:

- Background layers: `--bg`, `--bg-2`, `--bg-3`
- Text: `--fg`, `--fg-strong`, `--fg-dim`, `--fg-faint`
- Accents: `--accent`, `--green`, `--cyan`, `--magenta`, `--amber`, `--red`
- Structure: `--border`, `--radius`, `--shadow`
- Typography: `--mono`, `--sans`

Fourteen themes override these tokens: paper, dark, nord, dracula, sunset, dim,
synthwave, forest, abyss, retro, cyberpunk, halloween, autumn, coffee. The theme
is applied via `data-theme` on `<html>` and persisted as `av-theme`.

### Visual primitives

- Terminal window chrome (`.win`, `.win-bar`, traffic-light dots).
- Man-page layout (`.man`, `.man-bar`, `.man-sec`).
- Section headers with index and path.
- Dashed borders, mono labels, prompt glyphs.
- Neofetch layout.
- Skill manifest with proficiency tags.
- Project cards and note rows.
- Command palette overlay.
- Responsive rules at 680 px, 860 px, and related breakpoints.
- Reduced-motion overrides for boot, terminal, and reveal effects.

### Typography

System monospace stack for UI and code, system sans for long prose. No external
font request.

## 8. SEO, discovery, and security

### Metadata

- Canonical URLs from `Astro.site`.
- Open Graph and Twitter card metadata with a generated 1200×630 image.
- JSON-LD `@graph` containing `WebSite`, `WebPage`, and optional `Person`.
- `knowsAbout` covers systems, backend, C/C++/Rust/Python, Linux, embedded,
  ESP32, robotics, and open source.
- RSS alternate link.
- Sitemap with note `lastmod`.
- `llms.txt` and `llms-full.txt` for machine-readable summaries.

### Netlify headers

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- Restrictive `Permissions-Policy`
- CSP with `default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`
- Immutable caching for `/_astro/*`

The CSP currently requires `'unsafe-inline'` for both scripts and styles because
the theme boot script, footer clock, JSON-LD, and inline styles are embedded.

## 10. Invariants to preserve

1. Static output on Netlify; no runtime server requirement.
2. Astro + TypeScript + vanilla CSS + MDX; no React/Next migration.
3. Content remains file-based and deployable without a database.
4. The terminal remains functional and progressively enhanced.
5. All 14 themes continue to work, including light themes.
6. Keyboard access to navigation, palette, terminal, and theme picker.
7. `prefers-reduced-motion` is respected.
8. No fabricated projects, metrics, testimonials, or activity.
9. RSS, sitemap, JSON-LD, OG image, and `llms.txt` keep working.
10. Security headers remain strict; new features must not weaken them casually.

## 13. Constraints for implementation

- Keep the site static and deployable on Netlify.
- Prefer platform features over dependencies.
- Every interactive feature must have a no-JS or degraded path.
- New client JavaScript should be justified by an interaction that cannot be
  achieved with HTML/CSS.
- Do not add a design system dependency; extend the existing tokens.
- Do not rewrite content that the user has not verified.
- Measure after each phase; do not batch all validation to the end.

1. Any numeric claim must be either derived from content or carry an as-of date.
